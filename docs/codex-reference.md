# Codex workspace reference

Reviewed on 2026-10-24 against public `openai/codex` commit [`f970f4be6783428af0d39527102917a5305c71d7`](https://github.com/openai/codex/tree/f970f4be6783428af0d39527102917a5305c71d7).

The relevant public sources are the app-server protocol, client and TUI. They are not the desktop application's Projects sidebar implementation. The TUI's multiple-backend registration path is explicitly [under development](https://github.com/openai/codex/blob/f970f4be6783428af0d39527102917a5305c71d7/codex-rs/tui/src/app/backend_sessions.rs#L24-L34). These findings inform the goal of one workspace interface for local and remote work; they do not establish desktop implementation details or describe completed DSH features.

## Transferable principles

- **Keep a logical backend identity.** Codex separates [backend identity](https://github.com/openai/codex/blob/f970f4be6783428af0d39527102917a5305c71d7/codex-rs/tui/src/backend_id.rs#L1-L11) from transport connections and native thread IDs. Reconnecting or opening an auxiliary connection retains that owner. A [session selection](https://github.com/openai/codex/blob/f970f4be6783428af0d39527102917a5305c71d7/codex-rs/tui/src/resume_picker.rs#L111-L129) carries its backend, thread ID and reported working directory, and checks ownership before use. A unified workspace list likewise needs backend ownership alongside native workspace and session addresses; a path alone does not identify a machine.
- **Unify transport semantics.** The [client facade](https://github.com/openai/codex/blob/f970f4be6783428af0d39527102917a5305c71d7/codex-rs/app-server-client/src/lib.rs#L352-L362) represents in-process, remote and cloud clients. The [remote transport](https://github.com/openai/codex/blob/f970f4be6783428af0d39527102917a5305c71d7/codex-rs/app-server-client/src/remote.rs#L1-L10) deliberately shares the local event interface so higher-level session logic can stay the same. One visible application shell can select a backend without treating each connection as a separate application.
- **Keep each source independent.** [Backend sessions](https://github.com/openai/codex/blob/f970f4be6783428af0d39527102917a5305c71d7/codex-rs/tui/src/app/backend_sessions.rs#L1-L140) live independently of the displayed conversation; closing one event stream does not close the others. The [thread catalog](https://github.com/openai/codex/blob/f970f4be6783428af0d39527102917a5305c71d7/codex-rs/tui/src/resume_picker/catalog.rs#L1-L67) keeps pagination and pending requests per backend, retains cursors after errors for retry, and rejects stale completions after reset. A slow or unavailable source must not erase or block healthy sources.
- **Route events to their owner.** [Event handling](https://github.com/openai/codex/blob/f970f4be6783428af0d39527102917a5305c71d7/codex-rs/tui/src/app/backend_events.rs#L1-L46) checks backend ownership before consulting native-thread caches or changing the displayed conversation. Connection-wide account and lifecycle events from a background backend cannot overwrite the active backend's UI.
- **Respect path ownership.** For a remote backend, Codex [omits client-local workspace roots](https://github.com/openai/codex/blob/f970f4be6783428af0d39527102917a5305c71d7/codex-rs/tui/src/app_server_session.rs#L367-L374) and adopts the server's defaults or saved roots. Its [app-server path type](https://github.com/openai/codex/blob/f970f4be6783428af0d39527102917a5305c71d7/codex-rs/app-server-client/src/path.rs#L1-L41) follows the server path's platform rules. File, terminal and workspace operations must continue using the owning backend even when all work appears in one sidebar.

These boundaries allow a single workspace interface without combining remote state into local native records or replacing the backend's session lifecycle. The appropriate Harness extension points still need to be established separately.
